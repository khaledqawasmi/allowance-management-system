Testing

Testing Approach

The system was tested using Postman to verify the REST API endpoints, input validation, business logic, and database persistence. Both valid and invalid inputs were tested.


1. Allowance Testing

Test Case 1 – Create Daily Allowance

Endpoint: POST /allowance

Input: Valid allowance amount with Daily period.

Expected Result: The allowance is created successfully with 1 day.

Status Code: 201 Created

Result: Passed


Test Case 2 – Create Weekly Allowance

Endpoint: POST /allowance

Input: Valid allowance amount with Weekly period.

Expected Result: The allowance is created successfully with 7 days.

Status Code: 201 Created

Result: Passed

Test Case 3 – Create Monthly Allowance

Endpoint: POST /allowance

Input: Valid allowance amount with Monthly period using February 2026.

Expected Result: The allowance is created successfully with the correct number of days.

Status Code: 201 Created

Result: Passed


Test Case 4 – Create Yearly Allowance

Endpoint: POST /allowance

Input: Valid allowance amount with Yearly period using 2028.

Expected Result: The allowance is created successfully with the correct number of days.

Status Code: 201 Created

Result: Passed


Test Case 5 – Create Custom Allowance

Endpoint: POST /allowance

Input: Valid allowance amount with Custom period and a valid number of days.

Expected Result: The allowance is created successfully.

Status Code: 201 Created

Result: Passed


2. Spending Testing

Test Case 6 – Record Valid Spending

Endpoint: POST /spending

Input: Valid allowance ID and spending amount within the remaining balance.

Expected Result: The spending is recorded and the remaining balance, remaining days, and remaining daily budget are updated.

Status Code: 200 OK

Result: Passed

Verified Response:

{
    "allowance_id": 1,
    "message": "Spending recorded successfully.",
    "remaining_balance": 198.0,
    "remaining_daily_budget": 6.83,
    "remaining_days": 29,
    "spending_amount": 2.0
}


Test Case 7 – Spending Exceeds Remaining Balance

Endpoint: POST /spending

Input: Spending amount greater than the remaining balance.

Expected Response:

{
    "error": "Spending exceeds remaining balance."
}

Status Code: 400 Bad Request

Result: Passed


Test Case 8 – Negative Spending

Endpoint: POST /spending

Input: Negative spending amount.

Expected Response:

{
    "error": "Spending amount cannot be negative."
}

Status Code: 400 Bad Request

Result: Passed
